# Contributing

Thank you for helping with the site. It is the first thing people read
about passforme and the guide they come back to, so it moves carefully:
small changes, each one explained, each one checked.

## Before you write

- **A weakness in the site is reported privately**, never in an issue:
  see [`SECURITY.md`](SECURITY.md). A weakness in passforme itself goes
  to the [main repository](https://github.com/passforme/passforme/security/policy).
- **A mistake in the guide is an issue**, or a pull request if you know
  the fix. For anything beyond that, open an issue first, so that the
  idea is agreed before the work is done.
- **The guide documents the CLI as released.** It does not describe what
  passforme should do, only what it does; a change of behaviour starts in
  the main repository, and the guide follows it. Try a new example in a
  throwaway vault (`PASSFORME_DIR` pointing at a temporary directory)
  before writing it down.
- **Pages are edited in `src/`**, where every text exists in every
  language of the site: an element with `data-lang="pt"` next to its
  twin with `data-lang="en"`. `python3 tools/pages.py` writes `site/`
  from it, one file per language; commit both. If you can write only
  one language, open the pull request anyway and say so.

## The rules of the repository

[`AGENTS.md`](AGENTS.md) holds them in full, for people and their AI
agents alike. The short version:

- Everything is English, except the site's texts in their own languages:
  code, comments, docs, commit messages.
- Commits follow [Conventional Commits](https://www.conventionalcommits.org/)
  (`feat(site):`, `fix(site):`, `docs:`, …), one change per commit.
- Before every commit, and after any change to `src/` or to a file in
  `assets/`: `python3 tools/pages.py`, then `python3 tools/check.py`. CI runs the check. It fails on inline
  scripts or styles, resources from other domains, broken links and
  fragments, a text missing in one of the languages, or a page in
  `site/` older than its source.
- The site loads nothing from another domain and has no inline scripts
  or styles, so it can be served with a strict Content-Security-Policy;
  a change that needs either is a change to discuss first.
- The brand kit, the favicon and the icons are generated by
  `tools/brand.py`; change the palette or the mark there and run it,
  never the files.

## Signing your work

The site is licensed under the AGPL-3.0-only. By contributing you
certify the [Developer Certificate of Origin](https://developercertificate.org/):
that you wrote the change or have the right to submit it under this
license. Sign off every commit with `git commit -s`, which adds a
`Signed-off-by:` line with your name and email. No other paperwork.

## Pull requests

- One pull request per change, with the reason in the description.
- Preview it locally (the README says how) and look at both languages
  and both colour schemes.
- Reviews look at the diff, not the description: expect questions.
