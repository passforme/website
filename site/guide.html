Command guide

Every command of your password manager, from daily use to emergencies. An item's name can be just part of its title: pfm get deep finds deepseek.com.

Getting started

Once per laptop. The vault lives in ~/.local/share/passforme, encrypted.

pfm init create the vault

Asks for the master phrase (at least 12 characters) and shows the Emergency Kit: the Secret Key, which starts with SB1-. A phrase of words is easier to remember than a random password, and the generator suggests one.

pfm generate --words 6 --lang en # a master phrase suggestion
pfm init

Write the master phrase and the Secret Key on paper and keep it away from the laptop. Without both there is no recovery: the vault is encrypted on your device, and nobody else has the key.

pfm register URL link to a server (optional)

Without a server, pfm works on this laptop only. With your own passforme-server, the vault syncs between devices, and the server keeps only the encrypted vault. Registering takes a single-use invite, made on the server.

pfm register https://pfm.example.com

Daily use

Copy, look up, view. Anything copied to the clipboard is cleared by itself after 30 seconds.

Tab completes commands, options and kinds

Every option has a single, spelled-out name: --username, --generate, --symbols. To avoid typing it all, press Tab: pfm add x --us + Tab becomes --username, and --kind + Tab lists the kinds. An old short form such as -u answers with its new name.

To turn it on, add this line to your ~/.bashrc:

source <(passforme completions bash)

There are scripts for zsh, fish, elvish and powershell too:

passforme completions zsh > ~/.zfunc/_passforme # zsh

pfm get NAME copy a password

Copies the item's main secret: a login's password, a card's number, a PIN's PIN.

OptionWhat it does
--field usernamecopies the username
--field urlcopies the address
--field totpcopies the current 2FA code
--field cvv, --field pin, --field number…copies a field by name; a wrong name lists the ones that exist
--attachment NAMEsaves an attachment in the current directory, or where --output says; never overwrites
pfm get contabo
pfm get contabo --field username # copies the username
pfm get contabo --field url # copies the address
pfm get github --field totp # copies the current 2FA code
pfm get visa --field cvv
pfm get proton-recovery --attachment proton-recovery.txt --output ~/Desktop # saves the attachment in a folder

pfm list see every item

A table with title, kind, username, URL and what else each item holds: extra fields, 2FA, how many recovery codes are left, how many files are attached, and whether programs may read it. Never shows passwords.

pfm list
pfm list | grep -i kimi # filter

pfm show NAME see a whole item

Every field, with secrets as ********. With --reveal, the secrets are shown on screen. Attachments show as Attachment: name (size): that is where you find the exact name for get --attachment.

pfm show visa # secrets hidden
pfm show visa --reveal # secrets on screen

pfm totp NAME 2FA code

Shows the current 6-digit code and how many seconds it is still valid. To copy it: pfm get NAME --field totp. The 2FA secret goes in with pfm edit NAME --totp.

pfm totp github # shows the code
pfm get github --field totp # copies the code

pfm codes NAME recovery code

Copies the next unused code and marks it used. Warns when two or fewer are left. With --list, shows them all and which were used (on screen, in plain text). With --stdout, prints the code alone instead of copying it, for programs (see Agent). To add the codes, see recovery codes.

pfm codes openai # copies the next one and marks it used
pfm codes openai --list # all of them, (used) on the used ones
pfm codes openai --stdout # the code alone, not copied

A code cannot be unmarked: run pfm codes only when you are about to use one. Marking on copy errs on the safe side: at worst you are one code short, and a spent code never comes back to the list. To rebuild the list, paste the codes again with pfm edit NAME --codes.

Adding

A new password generated on the spot, a password you already have, or many at once.

pfm add NAME add an item

Without --generate, it asks for the password twice, to check it. Use it this way to keep a password you don't want to change.

OptionWhat it does
--username USERthe account's username or email
--url ADDRESSthe site's address; repeat it for several
--generategenerates a new password, saves it and copies it
--kind KINDthe kind of item (see Kinds); without it, a login
--file FILEreads the secret from a file, such as an SSH key
--agentlets programs (scripts, AI agents) read the item (see Agent)

With --generate, the generator options apply: --symbols, --length 16, --words 6… Without --generate, they are an error rather than ignored.

pfm add contabo.com --username root --url https://contabo.com --generate # new account
pfm add router --username admin --url http://192.168.1.1 # a password you already have
pfm add bank.com --generate --symbols # with symbols
pfm add app.com --generate --length 16 # a site that limits the length

pfm add-many many at once

Asks for label, password, label, password… until an empty Enter. The master phrase is asked once and every item is saved right away: stopping halfway loses nothing. A pasted password is not shown. Handy for bringing passwords over from another manager; fill in each item afterwards with pfm edit.

pfm add-many # Label: github.com, the password, Label: … an empty Enter finishes
pfm edit github.com --username you@example.com --url https://github.com # fill in later

Passwordless login SMS code, sign in with Google

For a site you enter through your phone or your Google account, add it without --generate and, when it asks for the secret, press Enter without typing anything: the item is saved without a password. It is still worth adding, because a year from now the hard part is remembering how you signed in.

  • --username: the phone number or email you used. For Google sign-in, the Google account's email, since with several accounts it is easy to forget which one.
  • Notes: the method ("sign in with Google", "SMS code"). add has no notes option: add them with pfm edit NAME --notes and finish the text with Ctrl-D on an empty line.
  • Recovery codes: if the site has 2FA and offers backup codes, keep them in an item of their own, of kind recovery-codes.
  • If the site ever starts asking for a password, generate one on the existing item with pfm edit NAME --generate.
pfm add uber.com --username "+1 555 010 0199" --url https://uber.com # empty Enter for the secret
pfm edit uber --notes # write the method; Ctrl-D finishes
pfm add "uber codes" --kind recovery-codes # 2FA backup codes
pfm edit uber --generate # if it starts asking for a password

Kinds of item

pfm add NAME --kind KIND asks for the kind's fields one by one; Enter skips a field. pfm kinds lists the kinds in the terminal. --username, --url and --file only apply to kinds that have that field, and --generate only to login, wifi and bank, whose secret is a password: a generated PIN, card or recovery phrase would make no sense.

KindForget copies
login (default)a site or app: username, password, URLs, 2FAthe password
notefree text—
recovery-codesbackup codes; one per line when pasting, an empty line finishes (examples)use pfm codes
recovery-phrasean account's recovery phrase (Proton…); BIP-39 checked when it is onethe words
security-questionssecurity questions and answers--field "the question"
pinphone, alarm, lockthe PIN
api-keyan API key or token: its name on the site, its expirythe key
crypto-seeda wallet's recovery phrase; checks the BIP-39 checksumthe words
ssh-keyan SSH or GPG key, read with --filethe private key
cardcardholder, number (check digit), expiry MM/YY, CVV, PINthe number
bankbranch, account, app and transaction passwords, Pix key (Brazil's instant payments)the app password
wifinetwork and passwordthe password
licensea software license keythe key
documentID, passport: number, dates, issuerthe number
pfm add visa --kind card
pfm add google-codes --kind recovery-codes
pfm add ledger --kind crypto-seed
pfm add ssh-github --kind ssh-key --file ~/.ssh/id_ed25519
pfm add "phone pin" --kind pin
pfm add "home wifi" --kind wifi --generate # the network's password, generated
pfm add chase --kind bank
pfm add passport --kind document
pfm add "bank questions" --kind security-questions # question → answer, until an empty question
pfm add "server notes" --kind note # free text; Ctrl-D on an empty line finishes
pfm add jetbrains --kind license
pfm kinds # lists the kinds and each one's fields

Recovery phrases and card numbers are checked as you type them. A swapped word or a wrong digit makes pfm warn you and ask before saving, while the paper is still in your hand.

pfm add NAME --kind api-key keep an API key

add asks for one field at a time, in this order, and Enter skips any of them. The key name is asked here already: no --set-field needed. The account and the URL can also come on the command line, with --username and --url, and then it asks only for the rest.

FieldWhat goes in it
Accountthe account the key came from, usually the email. It is the item's username under another name. If the key leaks, it tells you where to revoke it.
Key namethe name you gave the key on the site, such as john-laptop: with several keys on one account, it tells which to revoke
Keythe key, pasted; it is not shown
URLthe dashboard where the key was created
Expiresthe expiry; empty if it doesn't expire

With --agent, programs (scripts, AI agents) can read the key (see Agent). Use it only if a program will read the key; to copy and paste it yourself, leave it off, and the key never goes through the agent. In their configuration, use the whole title: deepseek would also match the deepseek.com login.

pfm add "deepseek api key" --kind api-key # asks for account, key name, key, URL, expiry
pfm add "deepseek api key" --kind api-key --username you@example.com --url https://platform.deepseek.com # account and URL on the command line
pfm add "deepseek api key" --kind api-key --agent # a key a program will read
pfm get "deepseek api key" # copies the key
pfm get "deepseek api key" --field account # copies the account's email
pfm edit "deepseek api key" --password # replace it with a new key
pfm edit "deepseek api key" --set-field "Key name" # change the name later, or on an item made before the field existed
pfm get "deepseek api key" --field "key name" # copies just the name

Several keys on one account: one item per key, with its name in the title too, such as deepseek api key laptop and deepseek api key server. Then get, list and the programs' configuration tell them apart by title alone.

One service, several logins one item per login

Some services have one login for the app and another for the API, like Kimi: the chat at kimi.ai signs in by phone, and the API platform at platform.kimi.ai by email or Google. Add one item per login, each with its own username, and the key in a third item.

With several items starting with "kimi", pfm get kimi answers "matches several items" and lists them. Use the exact title, which always wins, or a part only one title has.

pfm add kimi.ai --username "+1 555 010 0199" --url https://kimi.ai # chat, SMS code
pfm add platform.kimi.ai --username you@email.com --url https://platform.kimi.ai # API, email code
pfm add "kimi api key" --kind api-key # the key
pfm show kimi.ai # exact title

Several accounts on one service one item per account

Two Zoho, Google or AWS accounts are two items, each with its own username and password. Put what tells them apart in the title (personal, work, the domain), so get finds the right one.

pfm add "zoho.com personal" --username you@example.com --url https://www.zoho.com --generate
pfm add "zoho.com company" --username admin@company.com --url https://www.zoho.com --generate
pfm get "zoho.com company" # exact title
pfm get company # or a part only it has

One login, more than one email extra fields

If it is the same login, with the same password, and the account has other emails (the signup one, an alias, the recovery one), --username holds the one you type to sign in, and the others go in extra fields. The field name is free: Alias, Signup email, Recovery email, whatever makes sense to you.

Extra fields exist only in edit: add the item first, then the fields. If the other email signs in with another password, it is another login, and another item.

pfm add "zoho.com company" --username you@company.com --url https://www.zoho.com --generate # the email you sign in with
pfm edit "zoho.com company" --set-field "Signup email" # asks for the value, visibly
pfm get "zoho.com company" --field "signup email" # copies the field
pfm edit "zoho.com company" --rm-field "Signup email" # removes the field

pfm add NAME --kind recovery-codes recovery codes and their file

A site's 2FA backup codes (OpenAI, GitHub, Google…). The kind asks for the account and the URL, which can also come on the command line, and then the codes: paste them all, one per line, and finish with an empty line. A code with a space in it is fine. They are not shown.

If the site gave you a file with the codes, attach it with edit --attach as a copy of the original. The codes still go in the item, since pfm codes uses the item's.

pfm add "openai recovery codes" --kind recovery-codes --username you@example.com --url https://openai.com # paste; an empty line finishes
pfm edit "openai recovery codes" --attach ~/Downloads/openai-recovery-codes.txt # keeps the file
pfm codes openai # when you need one: copies it
pfm codes openai --list # which are left
pfm get "openai recovery codes" --attachment openai-recovery-codes.txt --output ~/Desktop # gives the file back
pfm edit github --codes # codes inside a login, or a new batch

Made new codes on the site? pfm edit NAME --codes --attach NEW_FILE replaces the codes and attaches the new file; --rm-attachment removes the old one. Then delete the file in ~/Downloads.

pfm add NAME --kind recovery-phrase recovery phrase and file

Services such as Proton give a recovery phrase (12 words) and sometimes a recovery file. The recovery-phrase kind asks for the account, the URL and the words. If the phrase has the length of a BIP-39 phrase (12, 15, 18, 21 or 24 words), pfm checks it: a swapped or mistyped word shows at once. Phrases of any other form are kept as typed.

The file goes in as an attachment, encrypted inside the item, with edit --attach. An item's attachments add up to 512 KiB at most: the whole vault travels on every sync, so only small files fit.

pfm add proton-recovery --kind recovery-phrase # account, URL and the 12 words
pfm edit proton-recovery --attach ~/Downloads/proton-recovery.txt # keeps the file in the item
pfm get proton-recovery # copies the words
pfm get proton-recovery --attachment proton-recovery.txt --output ~/Downloads # gives the file back
pfm edit proton-recovery --rm-attachment proton-recovery.txt # removes the attachment

get --attachment never overwrites a file and writes it readable by you only. Once the file is in pfm, delete the copy in ~/Downloads.

Editing and deleting

pfm edit NAME change an item

Changes only what you ask for; the password stays the same unless you use --generate or --password.

OptionWhat it does
--title NEWrenames it
--username USERchanges the username
--url / --rm-urladds / removes an address
--passwordtype a new password
--generategenerates a new password and copies it; only on login, wifi and bank items
--totppaste the 2FA secret (text or otpauth:// link)
--noteswrite notes; finish with Ctrl+D
--set-field NAMEcreates or changes a visible field
--set-secret-field NAMEcreates or changes a hidden field
--rm-field NAMEremoves a field
--codesreplaces the recovery codes
--attach FILEkeeps a small file in the item; one with the same name is replaced
--rm-attachment NAMEremoves an attachment
--kind KINDchanges the kind, losing nothing
--agent / --no-agentturns program access on or off
pfm edit deepseek --url https://chat.deepseek.com --url https://deepseek.com # addresses on an existing item; the password stays
pfm edit contabo --generate # changed the password on the site
pfm edit github --totp # turned on 2FA
pfm edit alarm --kind pin
pfm edit contabo --title contabo.com # renames it
pfm edit contabo --username new@example.com # changes the username
pfm edit deepseek --rm-url https://deepseek.com # removes an address
pfm edit router --password # type the new password, twice
pfm edit contabo --generate --symbols --length 20 # generate by the site's rules
pfm edit uber --notes # notes; Ctrl-D on an empty line finishes, empty removes them
pfm edit chase --set-secret-field "App password" # hidden field, typed without echo
pfm edit chase --rm-field "App password" # removes the field
pfm edit "deepseek api key" --agent # programs may read it; --no-agent undoes it

Attachments small files inside an item

A recovery file, codes in a .txt, a PDF with the words: edit --attach keeps the file inside the item, and get --attachment gives it back. Up to 512 KiB for all of an item's attachments; an attachment with the same name replaces the old one.

An attachment is always encrypted, together with the rest of the item: in the laptop's vault, in its .bak, on the server and in its history, and during sync. Programs (the agent) never receive attachments. It is in plain text in two places only, both by your doing: the original file, until you delete it, and the copy get --attachment writes (readable by you only, never overwriting anything). The server sees only the item's rough size, never the content or the file's name.

pfm edit proton-recovery --attach ~/Downloads/proton-recovery.pdf # attaches
pfm edit proton-recovery --attach a.txt --attach b.txt # several at once
pfm show proton-recovery # lists: Attachment: name (size)
pfm get proton-recovery --attachment proton-recovery.pdf # saves in the current folder
pfm get proton-recovery --attachment proton-recovery.pdf --output ~/proton.pdf # saves under another name
pfm edit proton-recovery --rm-attachment proton-recovery.pdf # removes
rm ~/Downloads/proton-recovery.pdf # once attached, delete the original

pfm rm NAME delete an item

Asks you to type the title back, to confirm. With a synced vault, the item goes from the other devices too.

pfm rm router # type the title to confirm

Generator

The default is the Contabo style: 29 letters and digits, 173 bits. Nothing that breaks in a form, and a double-click selects all of it.

pfm generate generate only, without saving

OptionWhat it does
--symbolswith symbols
--length Nlength, from 4 to 1024
--no-digits, --no-uppercase, --no-lowercaseleaves out digits, uppercase or lowercase
--avoid-ambiguousleaves out look-alike characters: l, 1, O, 0
--words Na phrase of N words instead of characters
--lang pt-br, --lang enlanguage of the words; only with --words
--separator Xwhat goes between the words (default -); only with --words
--copycopies instead of printing
pfm generate # Tguod41e8MFOYKBFPF30bSxnxeIkE
pfm generate --words 6 --lang en # unused-tingly-snowless-…
pfm generate --length 6 --no-lowercase --no-uppercase # a 6-digit PIN
pfm generate --symbols --length 20 # a site that demands a symbol and allows 20
pfm generate --avoid-ambiguous # to read and type by hand
pfm generate --words 5 --separator " " # words separated by spaces
pfm generate --copy # copies without showing it

No option is ignored: if one makes no sense in the command, pfm refuses it before asking for anything. Phrases and characters don't mix: --words takes no --length, --symbols, --no-… or --avoid-ambiguous. In add and edit, every generator option needs --generate.

Session and security

Session automatic

Type the master phrase once, and the next commands don't ask again. It locks after 15 minutes unused, when the screen locks, when the laptop suspends, or with pfm lock. It only applies to commands typed in a terminal.

To change the time, create ~/.config/passforme/config with one line:

session = 1h # or 30m; "off" always asks

pfm lock lock now

Closes the session and empties the agent. Good before lending the laptop or walking away.

pfm lock

pfm status see the state

Whether the session is open and for how long, whether the agent is running and with which items, and the sync server. It takes no item name.

pfm status

pfm passwd change the master phrase

Re-encrypts the vault under a new key. The Secret Key stays the same. Write the new phrase on the Emergency Kit. With a server, the other devices ask for the new phrase on their next sync.

pfm passwd # the current phrase, then the new one twice

Agent (programs)

Programs (scripts, AI agents) don't use the session. They only read the items you mark, and nothing else in the vault. If you allow it, they also keep the items they create themselves.

CommandWhat it does
pfm edit openrouter --agentmarks the item for programs
pfm unlockhands the marked items to the agent for 8 hours
pfm unlock --for foreveruntil you lock, reboot or log out
pfm unlock --for 2h geminionly the items named, for the time given
pfm get NAME --stdoutwhat the program calls to read the value
pfm edit "deepseek api key" --agent # 1. mark it
pfm unlock --for 8h # 2. release it, with the master phrase
pfm get "deepseek api key" --stdout # 3. what the program runs
DEEPSEEK_API_KEY="$(pfm get 'deepseek api key' --stdout)" ./my-script # in a script
pfm status # what the agent holds and for how long
pfm lock # empties the agent now

With no agent released, get --stdout outside a terminal fails at once, instead of waiting for a phrase nobody will type.

pfm unlock --writable programs that keep what they create

With --writable, a program can also store items in the vault, without the master phrase: an AI agent that creates test accounts in an application you authorized it to test keeps the password, the 2FA secret and the recovery codes there, and reads them back later. A program changes only the items programs created. Yours it still only reads, and only the ones marked --agent.

CommandWhat it does
pfm unlock --writableyou, in a terminal: releases reading and writing for 8 hours (takes --for and item names, as always)
pfm add NAME --agent-spacethe program creates an item; takes --username, --url, --generate and --kind
pfm edit NAME --agent-spacethe program changes an item programs created; the options of edit, except attachments and --agent
pfm get NAME --stdoutreads a value; with --field totp, the current 2FA code
pfm codes NAME --stdoutprints the next recovery code and marks it used
pfm list --agent-spacewhat the agent holds, without secrets
pfm unlock --for 8h --writable # you, once, with the master phrase
pfm add "acme test admin" --agent-space --username admin@example.com --url https://staging.example.com --generate # the program: an account with a generated password
echo "$PASSWORD" | pfm add "acme test user" --agent-space --username you@example.com # a password the program already has, on stdin
pfm get "acme test admin" --stdout # reads the password back
echo "$TOTP_SECRET" | pfm edit "acme test user" --agent-space --totp # keeps the 2FA secret
pfm get "acme test user" --field totp --stdout # the 2FA code right now
printf '%s\n' "$CODE_1" "$CODE_2" | pfm edit "acme test user" --agent-space --codes # keeps the codes, one per line
pfm codes "acme test user" --stdout # uses one code
pfm list --agent-space # what the agent holds
pfm status # shows whether the agent takes writes and how many changes wait

Each secret comes in on a line of stdin, never as an argument. What the program writes stays encrypted on the laptop, and your next command in a terminal (any of them: pfm list, pfm get…) brings those items into the vault and syncs. In pfm list they show as agent-made in the AGENT column.

  • Your items stay out of reach: edit --agent-space and codes --stdout refuse an item you created, marked or not.
  • An item of yours always wins a search: if a program creates an item called router, pfm get router still finds your OpenRouter.
  • Deleting is yours: programs neither delete nor attach files. Use pfm rm NAME.
  • Limits: up to 200 items created by programs, of up to 64 KiB each.

After a reboot or a pfm lock, what was written is not lost: it enters the vault with your next command. The program reads and writes again only after a new pfm unlock --writable. Treat what a program stored as coming from outside: it may have been written by the application it was testing.

Sync

Happens by itself on every add, edit, rm and codes. If the server is down, the change stays on the laptop and goes up next time. The server only keeps the encrypted vault.

CommandWhen to use it
pfm syncforce an exchange with the server
pfm register URLlink the vault to an empty server
pfm initcreate a new vault
pfm sync # after changing something on another device
pfm status # shows which server it is linked to

An item edited on two devices at once: the server's version stays and yours becomes "title (conflict)". Nothing typed is lost.

Emergency

Laptop broken, stolen or replaced? The vault comes back whole from your server, with the Emergency Kit.

pfm login URL set up a new device

Asks for the Secret Key (it starts with SB1-) and the master phrase, both from the Emergency Kit, and downloads the vault.

pfm login https://pfm.example.com

Without the Secret Key and the phrase there is no recovery: not even the server can open the vault. That is why the Emergency Kit stays on paper, kept away from the laptop.

No command matches that.
